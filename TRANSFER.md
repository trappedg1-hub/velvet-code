# Как передать проект другому агенту

Короткая шпаргалка. Всё уже упаковано, ничего собирать не нужно.

---

## Вариант 1 — через GitHub (лучший, если агент умеет работать с git)

Вы пушите один раз (команды ниже), дальше новый агент просто клонирует:

```bash
git remote add origin https://github.com/<USER>/<REPO>.git
git push -u origin main
```

Новому агенту говорите: «клон `https://github.com/<USER>/<REPO>`, прочитай `HANDOFF.md`»
и вставляете текст из блока «Что написать новому агенту» ниже.

Это единственный вариант, где прогресс продолжает копиться в облаке: агент коммитит и пушит
сам, вы видите историю, откат в любой момент.

## Вариант 2 — файлом-бандлом (если GitHub подключать не хочется)

`velvet-code.bundle` (11 МБ) — это **весь репозиторий с историей в одном файле**, не архив.
Скачайте его из воркспейса и отдайте агенту. Он поднимает проект так:

```bash
git clone velvet-code.bundle velvet-code && cd velvet-code
```

Важно: бандл — не «папка с файлами», а git-репозиторий. Клонировать его может любой агент,
у которого есть git; история и все коммиты сохранятся.

## Вариант 3 — папкой (если агент вообще без git)

Скачайте папку воркспейса целиком. Тогда вручную удалите то, что не нужно (см. ниже), и
обязательно передайте `HANDOFF.md` — он и есть проект, остальное восстанавливается.

---

## Что дать обязательно

| Что | Зачем |
|---|---|
| `HANDOFF.md` | вся история решений: что утверждено, что отклонено и почему, тупики, очередь работ |
| `AGENTS.md` | правила: гейты, формат отчёта, режим mature, запрет «чинить» тесты удалением |
| всё остальное из репозитория | код, канон, спрайты, карточки, прототип, доки |

## Что давать не нужно

| Что | Почему |
|---|---|
| `assets/raw/` (43 МБ) | промежуточные кадры на хромакее. Восстанавливаются из `assets/prompts/renders_v11.jsonl` → рендер → `make repair` |
| `review/*.html` | отчёты на утверждение, пересобираются одной командой `python3 automation/review.py` |
| `.arena/`, `__pycache__`, `.pytest_cache` | рантайм и кэши, в git их нет по `.gitignore` |

## Что написать новому агенту (копировать целиком)

```
Ты продолжаешь проект VELVET CODE — взрослая игра в стиле манхвы/хентай-аниме,
7 героинь, движок на PixiJS. Проект уже в работе, начинать с нуля не надо.

1. Сначала прочитай HANDOFF.md и AGENTS.md — целиком, до первой строчки кода.
   В HANDOFF: что утверждено (каст v11 — не переспрашивать), что отклонено 7 раз
   и почему, какие инструменты есть, какие тупики не повторять.
2. Проверь, что всё живо: make test (должно быть 103 passed), make canon-check.
   Если падает — сначала разберись, потом работай.
3. Режим работы: mature. Green — только витрина и гейт. Возраст подтверждён, правило 18+.
4. Не спрашивай разрешения на каждый шаг — владелец сказал «берём всё и делаем».
   Спрашивай только там, где выбор необратим (новый каст, смена регистра).
5. Стиль: уровень реальной манхвы/хентай-аниме. «Полуглянцевый AI-рендер» — брак.
   Персонажи без фона: хромакей → чистый альфа-спрайт, без артефактов.
6. Инструменты не перечисляй, а подключай: tools/prompt_forge.py, fabric.py,
   foot_spec.py, boldness.py, neg_audit.py, artifact_repair.py, pipeline_sprites.py,
   rig_anchors.py, build_slice.py, automation/arena_loop.py.
7. Возьми следующую задачу из ROADMAP.json (make next): layers-seethrough или rig-live2d.
8. Отчитывайся в формате:
   СДЕЛАНО / ПРОВЕРЕНО / ФАЙЛЫ / ЖДЁТ ЧЕЛОВЕКА.

Работай в репозитории, коммить после каждой законченной задачи понятным сообщением.
GitHub у меня не подключён — если попрошу, дай команды для push.
```

## Как проверить, что передача удалась

Новый агент после клона должен сам, без подсказок, показать:

```bash
python3 -m pytest tests -q        # 103 passed
python3 -m automation.canon check # canon ok
make slice                        # якоря + prototype/index.html
```

Если он этого не сделал — передайте ему этот файл и блок с текстом выше ещё раз.
