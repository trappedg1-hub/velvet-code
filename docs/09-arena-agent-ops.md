# 09 · Agent mode: как мы его используем

Ресёрч по GitHub, 20.11.2026. Задача: понять, чем **agent mode** можно управлять
программно, что из этого нам подходит, и где граница, за которую лезть нельзя.

---

## 1. Главный вывод

Официального API у Arena **нет**. Но на GitHub есть неофициальные мосты, которые
превращают залогиненную вкладку `arena.ai/agent` в **OpenAI-совместимый endpoint**.
Для нас это означает одно: любой наш скрипт может звать agent mode так же, как
любую LLM — через `base_url`, без SDK и без переписывания кода.

**Мы используем это как dev-ускоритель, а не как рантайм игры.** Причины в §5.

---

## 2. Что найдено на GitHub

### 2.1 `startify2647/ArenaAgentBridge` — основной инструмент

Локальный мост между агент-фреймворками (Hermes, OpenClaw, LiteLLM, Open WebUI,
curl) и реальной залогиненной вкладкой. MIT, версия 1.5.1 (24.09.2026), 21 коммит.

**Архитектура**

```
клиент (наш скрипт)  ──HTTP──▶  мост (FastAPI, 127.0.0.1:8000)
                                  │  POST /v1/chat/completions
                                  │  GET  /v1/models, /v1/bridge/status
                                  │  GET  /healthz, /readyz
                                  ▼
                              WS /ws/browser  ◀── расширение Chrome MV3 / Firefox 128+
                                  │                 (держит вкладку arena.ai/agent)
                                  ▼
                        DOM-автоматика: вставить промпт (React-safe),
                        нажать Send, поймать стрим (MutationObserver
                        + перехват page-world кадров a0:/ag:/ad:)
```

**Что важно знать перед подключением**

| Свойство | Значение | Следствие для нас |
|---|---|---|
| Очередь | **single-flight** | батчи только последовательные; не строим параллельные воркеры |
| Таймаут | 300 с на запрос | длинные задачи дробим на шаги |
| Типизированные ошибки | `captcha_required`, `login_required`, `dom_changed`, `page_timeout`, `browser_offline`, `queue_full` | первые четыре = **нужен человек**, не ретраить |
| Санитайзер | `detect`/`redact`/`off` (по умолчанию redact) | вырезает деструктивные команды из ответов страницы |
| Tool-calling broker (v1.5.0) | реализует контракт `api.openai.com` для `tools` | можно дать модели свои инструменты; **мост их не исполняет** — исполняем мы |
| Ключи | `AAB_REQUIRE_API_KEY`, `AAB_API_KEY`, `AAB_WS_TOKEN` | включаем, если мост живёт дольше одной сессии |
| Панель | `/admin` — история, правила санитайзера, состояние браузера, selfcheck | удобно смотреть, что модель реально получила |
| Тесты | 191 pytest + jsdom | проект живой, не заброшен |

**Переменные окружения** (полный список — в `.env.example` репозитория):
`AAB_HOST/PORT`, `AAB_DEFAULT_MODE=agent|direct`, `AAB_REQUEST_TIMEOUT`,
`AAB_QUEUE_MAX_SIZE`, `AAB_SANITIZE_MODE`, `AAB_REQUIRE_API_KEY`, `AAB_API_KEY`,
`AAB_WS_TOKEN`, `AAB_MOCK_BROWSER=1` (тесты без браузера), `AAB_PANEL_ENABLED`,
`AAB_HISTORY_SIZE`, `AAB_DOCS`.

`AAB_MOCK_BROWSER=1` — важная штука: позволяет прогнать весь наш клиент
без браузера и логина. Ровно то, что нужно для CI.

### 2.2 `Clyroas/Arena-Agent-Auto` — расширение-автоматизатор

Chrome side-panel: отправляет промпт **ровно один раз**, следит за DOM,
подхватывает ответ, ведёт историю. Своих сетевых запросов не делает
(`connect-src 'none'`). Полезно как ручной пульт, когда мост не нужен:
нажал — получил, без сервера.

### 2.3 `hishamalmushrea-cloud/agent` — Arena как «мозг» автономной платформы

Windows-платформа автономного агента (27 инструментов, слой разрешений
Safe/Sensitive/Dangerous, верификация, восстановление, персистентность) с
**Arena Agent Mode как подключаемым brain** по контракту делегирования.
Ценность для нас — не код, а **паттерн**: Arena планирует, исполнитель —
локальные инструменты с проверкой результата, не «чат, который что-то сказал».

### 2.4 Общий стандарт `AGENTS.md`

К 2026 `AGENTS.md` — де-факто стандарт инструкций для кодинг-агентов
(поддерживают Codex, Cursor, Copilot coding agent, Claude Code — через
`@AGENTS.md` в `CLAUDE.md`). Правила, которые реально работают:

- до ~150 строк в корне, вложенные файлы для подпакетов;
- **команды, а не проза**: точные строки, которые агент может выполнить;
- трёхуровневые границы: Всегда / Спросить / Никогда;
- критерий завершения («done = тесты зелёные, canon-check ok»), а не «сделай качественно»;
- «если застрял» — явный протокол остановки.

Это мы и сделали: `AGENTS.md` в корне проекта.

## 3. Как подключаем (пошагово)

```bash
# 1. мост
git clone https://github.com/startify2647/ArenaAgentBridge
cd ArenaAgentBridge
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # AAB_DEFAULT_MODE=agent, AAB_SANITIZE_MODE=redact
uvicorn main:app --host 127.0.0.1 --port 8000

# 2. расширение (Chrome: chrome://extensions → Developer mode → Load unpacked)
#    указать dist/chrome/ (или extensions/), открыть https://arena.ai/agent
#    и войти в аккаунт ВРУЧНУЮ. Мост капчу не решает и не обходит.

# 3. проверка со нашей стороны
export AC_PROVIDER=arena-bridge
make probe          # → {"ok": true, "models": ..., "status": ...}
```

Дальше любой наш скрипт:

```python
from automation.agent_client import AgentClient, from_env

brain = from_env()                                   # AC_PROVIDER=arena-bridge
answer = brain.chat([{"role": "user", "content": "…"}])["content"]
data   = brain.chat_json("ты — арт-директор", "…")     # строгий JSON, терпит ```-обёртки
```

Наш клиент уже нормализует поведение моста:

| Ситуация моста | Что делает наш клиент |
|---|---|
| `page_timeout`, `queue_full` | ретрай с экспоненциальной паузой (до 3 раз) |
| `captcha_required`, `login_required`, `dom_changed`, `browser_offline` | **не ретраит**, поднимает `AgentError(needs_human=True)` — задача уходит человеку |
| ответ в ```-блоке или с преамбулой | `extract_json()` достаёт объект |
| нет сети / CI | `AC_PROVIDER=mock` — детерминированные ответы без браузера |

## 4. Что именно автоматизируем

| Задача | Кто делает | Инструмент |
|---|---|---|
| Разбор референсов, сбор промпт-паков | agent mode (dev) | `agent_client.chat_json` + канон |
| Генерация черновиков реплик (4 настроения × 11 интентов) | agent mode (dev) | батч + ревью человеком |
| Ревью арта по QA-чеклисту | agent mode + `qa.py` | правила + LLM как второй фильтр |
| Суммаризация сессий в память героини (у игроков) | **обычный API** | нельзя на мосте — см. §5 |
| Рантайм-диалог в игре | **обычный API** | то же |
| Всё, что в CI | `mock` | без сети, детерминированно |

**Правило:** мост — только там, где результат проходит через человека
(контент, канон, ревью). Всё, что видит игрок в реальном времени — обычный
провайдер с SLA.

---

## 5. Почему не в рантайм игры

| Причина | Что будет, если проигнорировать |
|---|---|
| Нет официального API, обход через DOM | любое изменение вёрстки Arena ломает игру (`dom_changed`) |
| Капча/логин | игрок увидит «нужен человек» посреди сессии |
| Single-flight очередь | один игрок ждёт другого; задержка в секунды |
| ToS и юридический риск | аккаунт/проект могут отключить; авторы прямо пишут «personal use, ToS risk» |
| Нет SLA и метрик | нельзя обещать 99% uptime и p95-латентность |

Именно поэтому архитектура разделена: **dev — мост, prod — API.** Это же
снимает вопрос «а если мост умрёт завтра»: игра от него не зависит.

## 6. Паттерны agent mode, которые мы берём (и один, который нет)

**Берём:**

1. **Гейт утверждения** — то, что человек подписал, нельзя молча изменить. Реализовано:
   `canon.py` с хешами, `make canon-check` валит CI при расхождении.
2. **Spec-driven loop** — сначала спецификация (канон), потом код, потом проверка.
   Задача не считается сделанной без `make test && make canon-check`.
3. **Специалисты с минимальными правами** — не один агент на всё, а роли
   (арт-директор, геймдизайнер, QA) с разными правами: ревьюер не пишет файлы.
4. **Tool-calling broker** — модель планирует, инструменты исполняем мы
   (`forge`, `qa`, `canon`); мост только возвращает `tool_calls`.
5. **Очередь задач как данные** — `ROADMAP.json` + `make next`; человек нужен
   только на задачах с `owner: human`.
6. **Headless CI** — `mock`-провайдер + pytest + canon-check на каждый push.

**Не берём:**

- ❌ «Ralph loop» (бесконечный цикл, пока не сделает) на контенте: без человека
  в петле он гарантированно уедет в сторону от канона.
- ❌ Автономное исполнение разрушительных команд: санитайзер моста — хороший
  слой, но наша защита должна быть в правах, а не в промпте.

## 7. Гейт утверждения (как это работает на практике)

```
canon/source/*.json        человекочитаемый вход (стиль, состав, политика)
        │  make sync
        ▼
canon/canon.json           реестр: status + sha256 данных
        │  make canon-render
        ▼
review/canon-v1.html       лист на утверждение (спрайты встроены, 0 внешних запросов)
        │  человек смотрит и решает
        ▼
make approve ID=…          или в чате: «утверждаю style-core и cast-v1»
        │
        ├─ данные изменились после утверждения? → статус слетает в draft
        └─ make canon-check → CI падает, если утверждённое разошлось
```

Пока элемент в `draft`, фабрика **не имеет права** генерировать продакшн-арт.
Это и есть механизм «утвердил → запомнил → использую дальше».

## 8. Что уже лежит в репозитории

| Файл | Роль |
|---|---|
| `automation/agent_client.py` | клиент к мозгу: arena-bridge / openai / mock, типизированные ошибки, `probe`, `chat_json` |
| `automation/canon.py` | реестр утверждений + drift-детектор + экспорт approved |

| `automation/tasks.py` | очередь задач (`next` / `list` / `done`) |
| `canon/source/style-v1.json` | канон v1: стиль, словарь, состав, напряжение, политика |
| `AGENTS.md` | контракт для любого агента: команды, границы, формат отчёта |
| `.github/workflows/ci.yml` | гейты: pytest + canon-check + проверка синтаксиса прототипа |
