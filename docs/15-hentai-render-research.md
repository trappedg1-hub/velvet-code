# 15. Регистр hentai-render и анатомия стопы

Документ отвечает на два вопроса владельца: **почему предыдущий стиль читался как комикс** и
**что именно делает стопу привлекательной, а не «ластой»**. Плюс отдельная часть — как в проект
подключён турнирный движок агентов.

Коротко: стиль задают **характер линии и тень**, а не толщина контура и не количество тонов.

## 2. Регистр `hentai-render` (дефолт в `tools/prompt_forge.py`)

**Линия.** Тонкая, деликатная, переменная по толщине; кончики волос острые, волоски отдельные.
Толстый равномерный контур — запрещён: он и создаёт «комикс».

**Поверхность.** Мягкие градиенты, полуреалистичная кожа (градиент на скулах и переносице),
никаких жёстких cel-краёв. Матово-живописная тень, а не плашка.

**Тень кожи.** Насыщенная, **со сдвигом в красный/фиолетовый**, на Multiply. Именно цветная тень,
а не просто «темнее», даёт манхва-объём. Подчёркивает арку стопы, костяшки, колени.

**Блики.** Глянцевые точки **по форме**: губы как лак, многослойные блики в радужке, блик на голени,
плече, нейлоне. Не «пластиковый» airbrush — блик должен читаться как отражение источника.

**Свет.** Один тёплый ключевой + узкий rim light + отражённый цвет + лёгкий цветовой градиент-оверлей.

Промпт-ядро:

```
clean thin lineart, tapered line ends, soft gradient shading, saturated red-violet skin shadows,
glossy specular highlights, detailed iris with layered highlights, rim light, cinematic color grading
```

Запреты (в негатив):

```
flat cel shading, thick comic outline, spot blacks, screentone, airbrushed plastic skin, 3d render, chibi
```

Готовые дескрипторы-референсы для промпта: **Shindol** (мягкий cel-градиент, светящаяся кожа,
румянец, глянцевые многослойные блики глаз), **Manhwa Ultradetailed** (Redice Studio),
**Polished Ultrarealistic Anime Pin-Up** (губы и кожа как лак), **Thin Delicate Outline** (Kuvshinov).

### Источники
- Korean manhwa character illustration (Gat-Geul): иерархия толщины линии, тени кожи с красным/фиолетовым
  сдвигом, слои Multiply/Add-glow, rim light, правило трёх цветов, финальный overlay.
- Гайд по романтическому вебтуну (Comistitch): «никаких hard cel edges и глянцевых точек-заглушек»,
  мягкая живописная матовая тень, тёплый низкоконтрастный свет, волоски по отдельности.
- GeekVibesNation, manhwa art style: мягкие цифровые градиенты + rim light + отражённый цвет = «дорогой» вид.
- KusArt, «manhwa-sleek»: полуреалистичная кожа, градиент на скулах/переносице.
- Krea-2 style wildcards: Shindol, Manhwa Ultradetailed, Polished Ultrarealistic Anime Pin-Up,
  Thin Delicate Outline — готовые текстовые дескрипторы.

## 3. Стопы: почему были «ласты»

Причина не в модели, а в задании.

1. **Ракурс.** «Подошвой в камеру» — максимальное перспективное сокращение: длина и ширина стопы
   раздуваются. Любая нога в этом ракурсе читается как ласта. Такой ракурс был прямо прописан
   в позах Селены и Айрин и в тегах `soles / sole focus`.
2. **Негатив.** Не было анти-ласт тегов — модель рисовала длинные ступни с растопыренными пальцами.

### Анатомия, которая теперь в спецификации

- длина стопы ≈ **длина головы ≈ предплечье** (запястье→локоть);
- три **равных** блока: пальцы / свод / пятка;
- высота ≈ ширина, длина ≈ 3 высоты;
- у женской стопы уже пятка и лодыжка, выше свод, круче подъём, тоньше и короче пальцы;
- внутренняя лодыжка выше наружной; большой палец отделён и слегка вздёрнут, мизинец уходит
  вниз и внутрь, каждый следующий палец ≈ 1/3 объёма предыдущего;
- пальцы не «пять сосисок»: подушечки скрывают половину проксимальной фаланги.

### Ракурсы

| ракурс | оценка | почему |
|---|---|---|
| профиль | **лучший** | читаются свод, подъём и линия пальцев без искажений |
| три четверти | хороший | видно и подъём, и пальцы, сокращение умеренное |
| сзади | хороший | пятка и ахилл, сильный силуэт на каблуке |
| спереди на пальцы | осторожно | пальцы доминируют, легко получить «лопату» |
| подошвой в камеру | **запрещён** | максимальное сокращение — источник ласт |

При сильном сокращении рисуют **поперечные контуры**, а не силуэт.

### Что сделано в коде

- `tools/foot_spec.py` — пропорции, ракурсы, промпт-блоки, `check()`.
- `tools/prompt_forge.py`: при `feet_focus_level ≥ 2` анатомия подставляется автоматически,
  анти-ласт негатив добавляется всегда, а опасная формулировка позы **переписывается** на
  трёхчетвертной ракурс.
- Карточки `selena` и `irene`: позы исправлены на «трёхчетвертной ракурс, напряжённая арка».

```bash
python3 tools/foot_spec.py --views
python3 tools/foot_spec.py --block
python3 tools/foot_spec.py --check "<prompt>" "<negative>"
```

### Честный пробел

`qa_sprites` не видит анатомию: геометрический гейт считает «ласту» нормой. Проверка стопы поэтому
живёт **до** рендера, на уровне промпта. Дальше нужен отдельный foot-гейт по картинке
(отношение длина/ширина + наличие пяти пальцев), но это отдельная задача.

## 4. Турнир агентов подключён в репозиторий

Движок склонирован целиком, не пересказан:

```
vendor/arena-skill/
  bracket.py        # планировщик турнира и состояние
  SKILL.md          # 6 фаз: spawn → attack → defend → rewrite → judge → synthesize
  strategies.json   # карточки стратегий
  rubric.md         # слепое судейство
  LICENSE           # MIT
```

Обёртка `automation/arena_loop.py` собирает входные файлы из **нашего** канона и карточки героини,
поэтому турнир нельзя запустить «на пустом месте»:

```bash
python3 -m automation.arena_loop plan --agents 16
python3 -m automation.arena_loop init --heroine selena --heat 2 --agents 16 \
    --reject-reason "ушло в комикс: толстый контур и плоский cel"
python3 -m automation.arena_loop next
python3 -m automation.arena_loop status
python3 -m automation.arena_loop winner
```

План 16 агентов → 4 раунда → 92 вызова → 17 волн по 10. Для решений, определяющих продукт,
`--agents 100` → 7 раундов → 595 вызовов. Рубрика: correctness 30 / completeness 25 /
robustness 20 / specificity 15 / clarity 10; fatal-ошибка не выигрывает никогда.

Первый прогон: `.arena/run-20261120-100358-s7` — Селена L2, причина отказа «ушло в комикс»,
2160 карточек стратегий без повторов. Состояние в `.arena/` — рантайм, в снапшот не попадает:
пересоздаётся командой `init`.

## 5. Как Arena agent mode устроен (и почему это важно для проекта)

Arena agent mode даёт: веб-поиск, генерацию изображений, загрузку файлов, исполнение кода в песочнице,
запись файлов, уточняющие вопросы, плюс коннекторы (Vercel, Supabase, Drive, GitHub, Notion).
Публичного API нет — поэтому «подключить инструмент» здесь означает **положить код в репозиторий
и обернуть командой**, а не подписаться на внешний сервис. Именно так и сделано с `arena-skill`.
