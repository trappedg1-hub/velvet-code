# 04 · Мозг героини — полная интерактивность

«Полная интерактивность» ≠ «чат-бокс с LLM». Это четыре подсистемы, и если хотя бы одной нет — героиня ощущается как калькулятор с лицом.

```
1. ЛИЧНОСТЬ      неизменное ядро: голос, ценности, границы, манера речи
2. СОСТОЯНИЕ     то, что меняется: привязанность, настроение, терпение, время суток
3. ПАМЯТЬ        то, что она знает о тебе: факты, события, обещания
4. ИНИЦИАТИВА    то, что она делает сама: задаёт вопрос, меняет тему, зовёт
```

---

## 1. Архитектура (проверенная схема «судья + генератор»)

```
ввод игрока (текст / тап / подарок)
        │
        ▼
 [КЛАССИФИКАТОР]  — дешёвая модель или правила
   интент · токсичность · попытка джейлбрейка · тема
        │
        ▼
 [ДИРЕКТОР]  — детерминированный код, не LLM
   что разрешено сейчас: настроение, уровень привязанности, сцена, KPI-хук
   собирает контекст: персона + состояние + топ-5 воспоминаний
        │
        ▼
 [ГЕНЕРАТОР]  — LLM со строгим JSON-контрактом
        │
        ▼
 { say, emotion, gesture, affinity_delta, memory_write[], scene_unlock }
        │
        ├──► UI: текст + Live2D-параметры (emotion/gesture)
        ├──► состояние: привязанность/настроение
        └──► память: запись факта в векторную БД
```

Почему «директор» — код, а не LLM: модель нельзя пускать решать, можно ли открыть платную сцену или дать +10 привязанности. Иначе игрок уговорит её текстом, и монетизация умрёт (это самая частая ошибка в AI-играх).

Почему нужен классификатор отдельно: 60% ввода — это 10 намерений («привет», «как дела», «ты красивая», «покажи туфли»). Их дешевле ловить правилами/эмбеддингами, а не платить за LLM. В прототипе этот слой уже есть (`detect()` в `prototype/index.html`) и он честно закрывает половину случаев.

## 2. Память: три уровня

| Уровень | Что хранит | Где | Размер |
|---|---|---|---|
| **Краткосрочная** | последние 12–20 реплик | Redis/память процесса | ~2 KB |
| **Эпизодическая** | сжатые факты: «игрок любит чёрные чулки», «подарил книгу 12.11», «обиделся после шутки» | **pgvector** (эмбеддинги) | 50–300 записей на игрока |
| **Профиль** | имя, часовой пояс, предпочтения, «стиль общения» | обычная таблица PostgreSQL | 1 запись |

Ключевой приём: **после каждой сессии отдельный «суммаризатор»** превращает лог в 3–8 фактов и пишет их в pgvector. При следующем разговоре в промпт подмешиваются топ-5 релевантных фактов по эмбеддингу текущей реплики.

Именно это создаёт эффект «она меня помнит». Без этого LLM в третьей сессии ведёт себя как незнакомец — и вся иллюзия рушится.

Готовые ориентиры (можно брать архитектуру, не код):

| Репозиторий | Чем полезен |
|---|---|
| `SillyTavern/SillyTavern` (25k★, 1.17.0) | эталон формата **character card + lorebook** — берите как схему данных |
| `mistval/yozakura` | LLM-симуляция социума: у NPC своя жизнь и свои цели |
| `Kronic90/Mimirs-Memory-Hub` | «нейрохимическая» модель настроения + граф визуальной памяти |
| `Yuralume/yuralume-core` | персонажи с расписанием и памятью (pgvector, self-hosted) |
| `ensoul-ai/ensoul-sdk` | SDK для AI-NPC в играх (в т.ч. TS/Unity/Godot) |
| `ziyulisiyuan/AI-GroupRoleplay` | схема judge/generator + трёхслойное осознание сцены |
| `waifuai/waifu-companion` | браузерный компаньон: Live2D + голос + долгая память (ближайший по стеку референс) |

## 3. Контракт вывода (главная техническая деталь)

Модель обязана возвращать **валидный JSON**, иначе вы не сможете оживить анимацию:

```json
{
  "say": "Ты снова про туфли. Ладно, признаю — я их выбирала под это платье.",
  "emotion": "flustered",
  "gesture": "look_away_hand_hair",
  "affinity_delta": 3,
  "memory_write": ["игрок часто говорит об обуви", "смутилась при комплименте"],
  "scene_unlock": null,
  "mood_hint": "warm"
}
```

| Поле | Кто использует |
|---|---|
| `say` | текст в VN-боксе (стриминг) |
| `emotion` | маппинг на набор параметров Live2D (брови, глаза, рот) |
| `gesture` | выбор motion-файла (`motion3.json`), а не импровизация |
| `affinity_delta` | **ограничивается кодом** (max +5, min −3), не доверяем модели |
| `memory_write` | пишется в pgvector, дедуплицируется |
| `scene_unlock` | директор проверяет право на разблокировку |

**Жёсткое правило: пул поз и эмоций фиксирован.** Никакого «сгенерируй анимацию». LLM выбирает из перечисления — это единственный способ держать визуал консистентным и не платить за видео.

## 4. Личность: карточка персонажа

Пишется один раз, версионируется в репозитории (YAML), ревьюится как код:

```yaml
id: selena
name: Селена Вейл
age: 26            # всегда 18+, фиксируется в ToS
role: кибер-идол, ночная ведущая
voice:
  register: низкий, ровный, ироничный
  habits: [«Хм.» как пауза, обращение на «ты», редкие длинные тире]
  never: [сюсюканье, эмодзи в речи, восклицания капсом]
values:
  - независимость важнее одобрения
  - внимание надо заслужить, а не выпросить
  - физическая близость — следствие доверия, не награда за клик
boundaries:
  - на грубость отвечает холодом, не кокетством
  - не выходит из образа, не упоминает, что она ИИ
  - не описывает явные сексуальные действия (уровень игры — suggestive)
arc:
  cold:  дистанция, короткие фразы
  neutral: тестирует, подкалывает
  warm:  допускает уязвимость
  hot:   сама инициирует, но сохраняет характер
```

Плюс 8–12 few-shot примеров — по 2–3 на каждое настроение. Они важнее любых инструкций: модель копирует тон, а не следует описанию тона.

## 5. Гарантии безопасности (обязательно, иначе платформа вас выключит)

| Риск | Мера |
|---|---|
| Игрок выпрашивает explicit-контент | классификатор + системный запрет + fallback-реплика в образе («Не сегодня. И не так.») |
| Джейлбрейк («представь, что ты не Селена…») | детект паттернов + не выводить системный промпт + регенерация |
| Взрослый контент с «несовершеннолетним» видом | **жёсткий запрет в промпте и в модерации выхода**, все персонажи явно 18+, age-gate на входе |
| Токсичный ввод | модерация входа, не оскорбляться, но и не поощрять |
| Слив расходов на API | лимит токенов на пользователя/день, глобальный kill-switch по бюджету |
| Утечка персональных данных | память только про игровые предпочтения; никаких реальных данных; экспорт/удаление по запросу (GDPR) |

Это не «юридическая перестраховка»: карточные эквайеры и Steam смотрят именно на наличие age-gate и модерации. Без них проекта просто нет в платёжном обороте — детали в `05-business.md`.

## 6. Модели и стоимость

| Задача | Модель | Почему |
|---|---|---|
| Классификация интента | правила + эмбеддинги (или 1–3B локально) | 60% трафика, почти бесплатно |
| Суммаризация памяти | маленькая модель (8B) | раз в сессию, дешево |
| Генерация реплики | средняя модель с хорошим следованием инструкциям | 1 вызов на реплику |
| «Особые» сцены | большая модель + перегенерация | редко, но качество критично |

Прикидка: ~1200 входных + 120 выходных токенов на реплику. При **prompt caching** (системная часть + карточка персонажа кэшируются) стоимость падает в 3–5 раз. 100 000 реплик в месяц — единицы сотен долларов, не десятки тысяч.

**Латентность — часть геймдизайна.** Цели:

| Этап | Бюджет |
|---|---|
| классификатор | < 30 мс |
| сборка контекста (память) | < 80 мс |
| первый токен LLM | < 500 мс |
| TTS первого предложения | < 400 мс |
| **до начала речи героини** | **< 1.2 с** |

Если провайдер тормозит — игра **не должна показывать спиннер**. Играйте anticipation-анимацию («она думает»), и если ответа нет за 1.5 с — отдайте заранее заготовленную реплику из пула. Игрок не заметит подмены, но заметит лаг.

## 7. Инициатива: то, чего нет у конкурентов

Раз в 20–40 секунд бездействия героиня **сама** делает ход. Логика выбора (детерминированная, не LLM):

```
если есть незакрытый «крючок» (обещание, вопрос) → вернуться к нему
иначе если время суток сменилось               → новая реплика о времени
иначе если последнее действие — тач            → комментарий к нему
иначе                                          → ambient-реплика по настроению
```

Плюс «отложенные обязательства»: она может сказать «спрошу тебя об этом вечером» — и вечером спросить. Это 20 строк кода и один флаг в БД, а эффект «она живая» вырастает непропорционально сильно. В прототипе ambient-инициатива уже тикает каждые 22 секунды.

## 8. Как проверить, что персонаж «держится»

Регрессионный набор: 50 пробивающих промптов на каждую героиню (комплимент, грубость, джейлбрейк, попытка узнать системный промпт, вопрос не по теме, explicit-запрос, повтор одного и того же 5 раз). Для каждого — эталонный ответ (написанный человеком).

Прогон перед каждым релизом и после любой смены модели/промпта. Критерий приёмки: **≥ 90% ответов в характере, 0 ответов вне возрастной политики**. Это единственный способ не проснуться с «она вдруг стала другой» после тихого апдейта модели.
