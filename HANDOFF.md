# HANDOFF — передача проекта VELVET CODE другому агенту

Этот файл нужен, чтобы **любой новый агент вошёл в проект без переписки**. Всё, что было
выяснено за семь заходов, здесь: что утверждено, что уже отклонено владельцем и почему,
какие инструменты есть, чем проверять работу и что делать дальше.

Читать в таком порядке: этот файл → `AGENTS.md` (правила) → `ROADMAP.json` (очередь) →
`docs/README.md` (детали по темам) → `canon/source/style-v12.json` (действующий канон).

---

## 1. Что это

**VELVET CODE** — взрослая браузерная игра в жанре эччи / hot-fanservice, манхва-стилистика.
Семь героинь, у каждой своя фигура, темперамент и линия давления. Продукт делается фабрикой:
Python-инструменты собирают промпты, рендеры, спрайты, канон и отчёты на утверждение.

Стек: Python 3.13 (stdlib + PIL, numpy, cv2, pytest) — фабрика; самодостаточный HTML/JS — прототип;
дальше по плану Next.js и pixi.js v8 + Live2D.

**Где мы стоим:** каст из семи героинь отрендерен, очищен от артефактов и **утверждён владельцем
целиком** (20.11.2026). Собран вертикальный срез на всех семи. Следующая крупная работа — слои
для see-through или риг.

## 2. Что утверждено и что отклонено — не переспорить

### Утверждено
- **Регистр `hentai-render`** — тонкая переменная линия, мягкие градиенты, тень кожи с красно-
  фиолетовым сдвигом, глянцевый блик по форме, rim light. Это и есть «манхва/хентай-рендер».
- **Каст v11** — семь спрайтов `assets/sprite/m_*.webp`, рост 154–178 см, режим mature.
- **Режим mature как единственный рабочий** (см. §4).
- **Стопы маленькие** (0.75–0.85 головы), с аркой и ухоженными ногтями. Большие стопы — брак.

### Отклонено (не повторять)
- **v6** — «полуглянцевый AI-рендер».
- **Регистр B (v8)** — «ушёл слишком в комикс». Причина: толстый равномерный контур + плоский cel.
  **Стиль задаётся характером линии и тени, а не толщиной контура и не числом тонов.**
- **Equal-height composite** — все героини одного роста на листе. Только истинный масштаб.
- **«Ласты»** — расплющенные/перекошенные стопы. Отдельно: ракурс «подошвой в камеру» запрещён,
  он и даёт ласту.
- **Plump/plus-size** — не в этом проекте.
- Все героини — **взрослые** (25–34). Это не обсуждается и не «настраивается».

## 4. Режим Green / Mature

`tools/maturity.py` — гейт, а не надпись. Состояние: `canon/source/maturity.json`.

| режим | heat | смелость | смысл |
|---|---|---|---|
| `green` | ≤ 1 | ≤ 74 (B1) | витрина, подпись «одета» |
| `mature` | ≤ 3 | ≤ 200 | игра; выше 164 — только отдельный подписанный кадр |

Mature не включается без `--verify-age`. Форж спрашивает `cap()` и в green срезает heat.
**Сейчас репозиторий в mature, возраст подтверждён.** Владелец сказал: работаем только в нём.

```bash
python3 tools/maturity.py --status
python3 tools/maturity.py --verify-age
python3 tools/maturity.py --mode mature
python3 tools/maturity.py --resolve 2 141
```

| `python3 tools/neg_audit.py --check "…"` / `--clean "…"` / `--scan DIR` | саботаж в негативном промпте |

|---|---|

| `python3 tools/artifact_repair.py --fix RAW.png --out X.webp` | вылечить в правильном порядке |

| команда | порог |

### Арена и турниры
| команда | что делает |
|---|---|
| `python3 -m automation.arena_loop plan --agents 16` | план турнира |
| `python3 -m automation.arena_loop init --heroine selena --kind boldness --agents 16` | турнир на откровенность |

## 8. Известные долги и дефекты (не прятать)

1. **Один кадр на героиню.** Нет набора состояний cold/neutral/warm/hot — нужен для игры.
2. **Позы только стоя.** Сидячие кадры требуют реквизита, а реквизит попадал в спрайт (было у
   Селены и Айрин) — если делать, то либо инпейнтом, либо без мебели в кадре.
3. **Нет слоёв.** See-through и переодевание невозможны, пока спрайт — одна картинка.
4. **`qa_sprites` не видит анатомию.** Он ловит геометрию (кадр, ореол, размер), но «ласту»
   считает нормой. Проверка стопы живёт на уровне промпта, до рендера.
5. **Кисти рук** в игре надо гонять через ADetailer — на спрайтах читаются нормально, но запас
   качества небольшой.
6. **Промпты каста — не метаданные.** Они лежат в `renders_v11.jsonl`, а не в манифесте;
   при пересборке спрайта руками легко потерять связь кадр↔промпт.

## 10. Как работать с владельцем

- Он **не любит защиту отвергнутого**. Если стиль отклонён — менять подход, а не объяснять.
- Он **требует внешний ресёрч с конкретикой** («изучи на гитхабе, можно с примерами»), а не
  рассуждения по памяти.
- Он **требует подключать инструменты, а не перечислять их**: код в репозитории + команда.
- Формат ответа, к которому он привык: **СДЕЛАНО / ПРОВЕРЕНО / ФАЙЛЫ / ЖДЁТ ЧЕЛОВЕКА**.
- Дефекты называть самому, до того как он их найдёт.
- Каждый шаг заканчивать гейтами (`pytest`, `qa_*`, `canon check`) и говорить цифры.

## 11. Тупики (не повторять)

- Толстый равномерный контур и плоский cel → «комикс».
- Лист с равным ростом → искажает каст.
- Ракурс подошвой в камеру → «ласта».
- Заливка «дырок» по внешнему контуру → чёрная плита позади фигуры.
- `safety_checker`/фильтры чужих сервисов: не обходим, а владеем локальным стеком.
- Парсинг корпуса промптов без паузы → 429; `length=100` → обрезанный JSON.
- Генерация с реквизитом (пуф, блок, стол) → реквизит попадает в спрайт.
- Модель охотно рисует надписи: в промпте всегда `no text, no watermark`.

## 11a. Память проекта

`MEMORY.md` — дамп памяти агента, который вёл проект: состояние и числа гейтов, журнал всех
заходов, внешние источники (URL + вывод), тупики, ключевые числа, правила общения с владельцем.
HANDOFF — «что делать», MEMORY — «что знаем». Новый агент читает оба, в этом порядке:
сначала MEMORY §1–3, потом HANDOFF целиком.

## 12. Как это сохранить на GitHub

Репозиторий инициализирован здесь же, история уже есть:

```
8cf0ab1 ci и правила: реальные гейты вместо заглушек
5d8161c доки и передача: 18 документов + HANDOFF для другого агента
e30a9a5 ассеты: утверждённый каст v11 и вертикальный срез
0993005 инструменты: форж промптов, ткань, стопа, смелость, негатив, артефакты, арена
8b8e048 база: карточки героинь, канон v12 (46 элементов), правила, очередь
```

Ветка `main`, рабочее дерево чистое, `.git` весит 12 МБ. Нужен только адрес:

```bash
git remote add origin https://github.com/<USER>/<REPO>.git
git push -u origin main
```

Пароль — **personal access token** (Settings → Developer settings → Personal access tokens,
права `repo`), не пароль от аккаунта.

**GitHub-коннектора у агента нет**, но сеть в песочнице открыта, поэтому пуш делается по токену:

```bash
GH_TOKEN=<fine-grained-token> tools/push_github.sh <user>/<repo> --check
GH_TOKEN=<fine-grained-token> tools/push_github.sh <user>/<repo>
```

Скрипт проверяет доступ через API, пушит `main`, затем **перезаписывает remote на чистый URL**,
чтобы токен не остался в `.git/config`. Право токена — только `Contents: Read and write`
на один репозиторий, срок минимальный, после работы отозвать.

**Если пушить нечем прямо сейчас** — рядом лежит `velvet-code.bundle` (полная история одним
файлом, 11 МБ). Другой агент/машина поднимает проект так:

```bash
git clone velvet-code.bundle velvet-code && cd velvet-code
```

Обновить бандл после новых коммитов: `make bundle`.

**Что в git не попадает** (`.gitignore`) и как восстанавливается:

| не в git | почему | восстановить |
|---|---|---|
| `assets/raw/` (43 МБ) | промежуточные кадры на хромакее | `assets/prompts/renders_v11.jsonl` → рендер → `make repair` |
| `review/*.html` | отчёты на утверждение, 2–3 МБ | `python3 automation/review.py` |
| `.arena/`, кэши | рантайм турниров и Python | `python3 -m automation.arena_loop init` |

CI (`.github/workflows/ci.yml`) на каждый push: pytest → qa_sprites → qa_render →
neg_audit → filter_audit → `canon check` → сборка отчёта → схема карточек (возраст ≥ 18,
≥ 6 зон) → `node --check` по JS прототипа.

**Без закрытых ключей и токенов.** `.env.example` — только имена переменных; реальный `.env`
в git не кладём никогда.
